# 한계와 다음 검증

이 문서는 프로젝트가 실제로 측정한 것과 아직 측정하지 않은 것을 분리한다. 단일 이미지 추천과 데이터셋 분류 평가는 다른 목적과 증거 수준을 가진다.

## 휴리스틱 추천의 한계

Advisor는 밝기, 대비, 노이즈, 에지, 색상, 클리핑 같은 진단 변화와 프로필별 가중치로 후보를 순위화한다. 적합도 점수는 분류 정확도를 뜻하지 않는다. 특정 파이프라인이 과업 성공이나 분류 성능을 보장한다는 뜻도 아니다. 점수는 정답 레이블이 없는 이미지에서 실험 우선순위를 투명하게 제안하는 휴리스틱이다.

가중치와 경고 규칙은 구현 가능한 판단 기준이지만, 모든 촬영 장비, 재질, 조명, 과업을 대표하지는 않는다. 실제 운영 전에는 목표 과업의 레이블, 오류 비용, 시각적 요구사항에 맞춰 후보와 파라미터를 검증해야 한다.

## 데이터셋 특이성

117장, 6개 클래스, seed 42의 MVTec tile 사례는 `tile/test`의 상태 폴더를 분류 클래스로 해석한 한 데이터셋 실험이다. Original + RTrees가 최고였다는 결과는 해당 데이터, 고정 특징, 선택한 파이프라인, 5-fold 분할에서의 관찰이지 모든 산업 이미지나 모든 MVTec 클래스에 대한 최적화 주장이 아니다.

다음 검증은 다른 클래스, 촬영 조건, 분할 seed, 파라미터 범위에서 동일한 보고서를 생성하고 변동을 비교해야 한다. 특히 데이터 수가 적을 때는 fold별 분산과 클래스별 지표를 평균 성능과 함께 읽어야 한다.

## GT와 MVTec 공식 평가의 부재

이 프로젝트는 이상 영역 GT mask를 사용하지 않았고 anomaly localization을 평가하지 않았다. 또한 결과는 MVTec의 공식 anomaly-detection 프로토콜이나 공식 MVTec anomaly-detection metric 이 아니다. `tile/test`의 하위 폴더 이름을 여섯 클래스의 레이블로 사용한 고전 분류 사례다.

따라서 AUROC, pixel-level AUROC, PRO처럼 공식 anomaly-detection 주장에 필요한 지표를 이 결과에서 유추할 수 없다. 그런 주장을 하려면 적합한 train/test 설정, GT mask, 공식 정의에 맞는 평가 코드를 별도로 구현하고 검증해야 한다.

## 고전 특징과 분류기의 한계

현재 비교는 HSV/LAB 히스토그램, HOG, Sobel/Laplacian/Gabor 통계와 OpenCV `cv2.ml`의 SVM, kNN, RTrees에 집중한다. 이 선택은 OpenCV 중심의 재현 가능한 기준선을 제공하지만, 깊은 특징, 학습된 표현, 모든 OpenCV API, 또는 모든 분류기를 포괄하지 않는다.

`SiftBowExtractor`는 독립 구현되어 있지만 현재 `BenchmarkService`의 특징 프로필로 제공되지 않으므로 리더보드의 비교 대상이 아니다. SIFT 어휘를 각 훈련 fold에서만 적합하는 향후 fold별 어휘 학습 통합이 이뤄진 뒤에야 공정한 벤치마크 비교에 넣을 수 있다. 표준화와 SIFT 어휘 같은 학습 단계는 fold-local하게 처리하지 않으면 누수가 생긴다. 다음 실험에서는 특징 프로필별 ablation, 파라미터 탐색, 보류 데이터셋 검증, 오류 사례의 정성 검토를 추가할 수 있다.
