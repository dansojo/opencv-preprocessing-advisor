# OpenCV Portfolio Evidence Map

Every portfolio statement below is tied to an implementation path and a regression test. The advisor ranks preprocessing candidates for a single image, while cross-validation evaluates classifier results on labeled data; these are intentionally separate claims.

| Area | OpenCV technique | Why it is used | Source | Test | Portfolio explanation |
| --- | --- | --- | --- | --- | --- |
| Image representation | BGR ndarray decoding and normalization | Gives every pipeline a predictable OpenCV input | `src/opencv_preprocessing_advisor/io.py` | `tests/test_io.py` | Inputs are decoded once into the representation expected by OpenCV. |
| Color spaces | BGR, grayscale, HSV, and LAB conversion | Separates luminance from color and supports color-aware features | `src/opencv_preprocessing_advisor/transforms.py` | `tests/test_transforms.py` | The project chooses representations based on the diagnostic task, not display preference. |
| Enhancement | normalization, gamma, and CLAHE | Repairs exposure and local contrast when diagnostics identify a need | `src/opencv_preprocessing_advisor/transforms.py` | `tests/test_transforms.py` | Contrast enhancement is a candidate operation with measurable trade-offs. |
| Filtering | Gaussian, median, and bilateral filtering | Reduces different noise patterns while preserving useful detail when possible | `src/opencv_preprocessing_advisor/transforms.py` | `tests/test_transforms.py` | Filtering is selected as a reproducible pipeline step, not a one-off edit. |
| Gradients | Sobel and Laplacian statistics | Quantifies edge strength and texture for diagnosis and features | `src/opencv_preprocessing_advisor/diagnostics.py` | `tests/test_diagnostics.py` | Gradient evidence helps distinguish sharp structure from noisy detail. |
| Morphology | black-hat and structuring elements | Emphasizes dark local structures in shape and texture workflows | `src/opencv_preprocessing_advisor/transforms.py` | `tests/test_transforms.py` | Morphology is exposed as an explicit, parameterized preprocessing choice. |
| Thresholding | Otsu binary threshold | Demonstrates binary segmentation decisions in the technique explorer | `ui/technique_explorer.py` | `tests/test_ui_imports.py` | The UI explains when thresholding is appropriate and when illumination makes it risky. |
| Contours/components | `findContours` and connected components | Measures and visualizes segmented object boundaries and regions | `ui/technique_explorer.py` | `tests/test_ui_imports.py` | Exploratory views connect segmentation primitives to visible image structure. |
| Diagnostics | brightness, contrast, entropy, sharpness, noise, and edge metrics | Turns image condition into a reproducible recommendation input | `src/opencv_preprocessing_advisor/diagnostics.py` | `tests/test_diagnostics.py` | The advisor starts from measured image characteristics rather than visual guesswork. |
| HOG | `cv2.HOGDescriptor` | Captures gradient-based shape information for classification | `src/opencv_preprocessing_advisor/features.py` | `tests/test_features.py` | HOG is one component of a combined feature profile. |
| Histogram | HSV and LAB color histograms | Captures color distribution independent of individual pixels | `src/opencv_preprocessing_advisor/features.py` | `tests/test_features.py` | Histograms complement shape and texture features. |
| Gabor | oriented Gabor filter responses | Summarizes directional texture across several angles | `src/opencv_preprocessing_advisor/features.py` | `tests/test_features.py` | Gabor statistics make texture evidence explicit in the model input. |
| SIFT | `cv2.SIFT_create` bag of visual words | Supports optional local-keypoint feature experiments | `src/opencv_preprocessing_advisor/features.py` | `tests/test_features.py` | SIFT is implemented as an optional feature path, with vocabulary fitting safeguards. |
| SVM | `cv2.ml.SVM_create` | Provides a nonlinear OpenCV classifier baseline | `src/opencv_preprocessing_advisor/classifiers.py` | `tests/test_classifiers.py` | SVM is evaluated under the same fold plan as other classifiers. |
| kNN | `cv2.ml.KNearest_create` | Provides a local-neighborhood comparison baseline | `src/opencv_preprocessing_advisor/classifiers.py` | `tests/test_classifiers.py` | kNN is compared rather than assumed to be suitable. |
| RTrees | `cv2.ml.RTrees_create` | Provides a tree-ensemble comparison model | `src/opencv_preprocessing_advisor/classifiers.py` | `tests/test_classifiers.py` | RTrees produced the reported best MVTec tile combination. |
| Cross-validation | stratified K-fold splitting | Keeps class balance and evaluation conditions consistent | `src/opencv_preprocessing_advisor/evaluation.py` | `tests/test_evaluation.py` | Reported benchmark metrics come from reproducible folds, not a single split. |
| Metrics | accuracy, macro F1, precision, and recall | Makes class-balanced performance and errors inspectable | `src/opencv_preprocessing_advisor/evaluation.py` | `tests/test_evaluation.py` | Macro F1 is reported beside accuracy to avoid a single-number narrative. |
| Reporting | CSV, JSON, PNG, and configuration hashes | Leaves an auditable record of predictions, metrics, and run settings | `src/opencv_preprocessing_advisor/reports.py` | `tests/test_reports.py` | Portfolio claims can be traced back to generated artifacts. |
| Streamlit integration | page routing and service calls | Makes the same application services usable in an interactive interface | `app.py` | `tests/test_ui_imports.py` | The UI is a thin layer over the tested service and reporting workflow. |
