# OpenCV Preprocessing Advisor 사례 연구

이 문서는 README, PDF, Notion에서 재사용하는 프로젝트의 정본 설명이다. 모든 기술 선택은 [증거 맵](evidence-map.md)의 구현 경로와 테스트로 추적할 수 있다.

## 문제 정의

이미지를 보기 좋게 만드는 전처리와 분류에 실제로 도움이 되는 전처리는 같은 문제가 아니다. 나는 이 차이를 명확히 하기 위해 프로젝트를 두 모드로 분리했다. 단일 이미지 Advisor는 정답 레이블이 없는 한 장의 이미지를 진단하고, 탐색할 가치가 있는 전처리 후보 세 개를 투명한 휴리스틱으로 추천한다. Dataset Benchmark는 클래스 폴더 구조와 레이블이 있는 데이터셋에서 같은 전처리가 교차 검증 분류 성능에 미치는 영향을 측정한다.

따라서 Advisor의 적합도 점수는 분류 정확도가 아니다. 이 점수는 다음 실험을 위한 우선순위이며, 일반화 성능에 관한 결론은 데이터셋 교차 검증 결과에서만 낸다.

## 단계 진단

`diagnostics.py`는 밝기, 명암, 엔트로피, 선명도, 노이즈 추정치, 조명 불균일, 에지 밀도와 연속성, 색상성, 채도 분산, 밝고 어두운 클리핑을 계산한다. 나는 이미지의 조건을 먼저 수치화한 뒤에 후보 파이프라인을 실행하고, 전후 진단값을 다시 비교한다. 이 순서는 시각적 인상만으로 필터를 고르는 과정을 재현 가능한 판단으로 바꾼다.

추천 점수는 프로필별 가중치를 둔 구성 요소로 이루어진다. 예를 들어 자동 프로필은 국소 대비, 엔트로피, 노이즈 감소, 선명도, 에지 연속성, 클리핑 제어를 함께 본다. 색상 프로필은 색 보존과 채도 분리를 추가로 중시한다. 결과에는 높은 기여를 한 이유와 클리핑, 과도한 에지, 과도한 평활화, 색 손실 경고를 함께 남긴다. 사용자는 점수뿐 아니라 어떤 진단 변화가 그 점수를 만들었는지 확인할 수 있다.

## 단일 이미지 추천

파이프라인은 YAML 설정으로 정의하고, 적용 가능한 프로필에서만 실행한다. 이렇게 하면 같은 입력과 설정에서 같은 후보와 중간 결과를 다시 생성할 수 있다.

LAB L-channel CLAHE는 BGR의 세 채널을 각각 평활화하지 않고, LAB로 변환한 뒤 밝기 채널인 L에만 CLAHE를 적용한다. a와 b 색상 채널을 그대로 두므로 채널별 BGR 평활화보다 색상 관계를 덜 교란하면서 국소 대비를 높이는 선택이다. 이는 색상 자체가 단서인 이미지에서 특히 중요한 설계 원칙이다.

필터는 서로 다른 노이즈 가정을 표현한다. Gaussian은 넓게 퍼진 고주파 노이즈를 완화하는 기본 선택이고, median은 점 형태의 임펄스 노이즈에 맞춘다. bilateral은 공간 거리와 색상 차이를 함께 고려해 에지를 더 보존하려는 경우에 사용한다. 어느 필터도 항상 우수하다고 가정하지 않으며, 결과 진단과 경고를 비교해 후보를 해석한다.

## 데이터셋 검증

데이터셋 모드는 원본 또는 선택한 전처리를 각 이미지에 적용한 뒤, OpenCV 고전 특징과 분류기를 같은 재현 조건에서 비교한다. 결합 특징은 HSV/LAB 색상 히스토그램, HOG, Sobel·Laplacian·Gabor 텍스처 통계로 구성한다. `SiftBowExtractor`는 독립적으로 구현되어 있지만 not exposed as a BenchmarkService feature profile 이다. 따라서 현재 보고한 실험 조합은 결합 특징이며, SIFT를 벤치마크에 넣으려면 future fold-local vocabulary integration 이 필요하다.

분류기는 `cv2.ml`의 SVM, kNN, RTrees다. 고정 OpenCV 특징과 `cv2.ml` 분류기를 사용함으로써 특징 추출부터 분류까지 프로젝트의 핵심 경로를 OpenCV 중심으로 유지했다. 모델 선택은 사전 선호가 아니라 같은 fold, 같은 특징 행렬, 같은 순위 기준 아래의 비교 결과에 따른다.

누수를 막기 위해 fold-local scaling을 사용한다. 각 fold에서 Standardizer는 훈련 인덱스의 특징만으로 평균과 표준편차를 적합하고, 그 값으로 훈련/테스트 특징을 각각 변환한다. SIFT 어휘처럼 학습되는 특징 표현도 훈련 fold에만 적합해야 한다. 이 경계가 없으면 테스트 데이터의 분포가 훈련 과정에 섞여 성능 추정이 낙관적으로 변한다.

## 종합 결과

프로젝트는 단일 이미지에서 설명 가능한 Top 3 탐색 순위를 제공하고, 별도 데이터셋에서 Macro F1, accuracy, 클래스별 precision/recall/F1, 혼동행렬, 처리 시간을 보고한다. 보고서는 CSV, JSON, PNG, 실행 설정 hash, OpenCV 버전, seed를 저장하므로 추천과 평가의 근거를 다시 확인할 수 있다.

MVTec tile 사례에서는 원본 파이프라인과 RTrees 조합이 Accuracy 0.804, Macro F1 0.789로 세 전처리 후보 중 가장 높았다. 원본 파이프라인이 이긴 것은 실패가 아니라 유용한 엔지니어링 결론이다. 이 데이터와 특징 조합에서는 원본 질감과 클래스 구분 정보가 이미 충분했으며, 대비 강화나 평활화가 항상 더 나은 표현을 만들지는 않는다는 사실을 보여 준다. 정확한 설정과 세 후보의 수치는 [실험 결과](experiment-results.md)와 경로를 포함하지 않는 [재생성 증거 요약](benchmark-evidence.json)에 기록한다.

## 실패 분석

CLAHE + Bilateral과 LAB CLAHE가 원본보다 낮은 Macro F1을 보인 관찰은 전처리를 많이 적용할수록 성능이 좋아진다는 가정을 반박한다. 관찰된 결과에 대한 가설은 다음과 같다: 국소 대비 강화가 tile 표면의 일부 클래스 간 미세 질감 차이를 과장하거나 바꾸었고, bilateral 평활화가 분류에 유용한 약한 질감 변화를 줄였을 수 있다. 이는 원본 데이터와 생성된 보고서에 근거한 해석 가설이며, 다른 데이터셋에 일반화한 인과 결론은 아니다.

이 사례는 MVTec의 anomaly localization이나 공식 anomaly-detection 평가가 아니다. `tile/test` 하위 상태 폴더를 여섯 분류 클래스로 해석한 제한된 분류 실험이므로, GT mask 기반 지표나 공식 MVTec 성능을 주장하지 않는다. 적용 범위와 다음 실험은 [한계](limitations.md)에 분리해 기록한다.
