# 진도 및 설명 능력 체크리스트

이 표는 일정표가 아니다. **시간 제한 없음**: 각 Day는 이해·구현·해석·설명 증거가 남을 때 완료한다. 체크 표시는 “읽음”이 아니라 다시 실행하거나 자신의 말로 설명할 수 있음을 뜻한다.

## 사용하는 방식

1. Day를 마친 뒤 네 증거를 남긴다: 실행 코드/명령, 결과 캡처 또는 수치, 실패·수정 메모, 1분 설명 녹음·대본.
2. 증거 링크는 커밋, 노트, 스크린샷, 테스트 로그처럼 본인이 다시 열 수 있는 위치를 적는다. 민감한 이미지·절대 경로·자격 증명은 적지 않는다.
3. 막힌 항목은 “다시 학습 backlog”로 옮기고, 이미 끝낸 Day를 다시 보는 것을 실패로 취급하지 않는다.

## 개념별 4단계 숙련도

4단계는 순서대로만 올라갈 필요가 없다. 한 주제를 구현할 수 있어도 설명이 약하면 해당 단계에서 멈춘다.

| 단계 | 의미 | 확인 질문 | 남길 증거 |
| --- | --- | --- | --- |
| 1. 인지 | 용어와 입력·출력의 의미를 안다. | “BGR, LAB L, Macro F1은 무엇인가?” | 짧은 정의와 API 링크 |
| 2. 재현 | 문서를 보고 같은 결과를 다시 만든다. | “합성 타일에서 코드를 실행할 수 있는가?” | 실행 명령, 코드, 결과 |
| 3. 해석 | 수치·이미지·실패를 이유와 함께 읽는다. | “엔트로피 상승이 왜 개선이 아닐 수 있는가?” | 전후 표, 반례, 선택 근거 |
| 4. 전이·설명 | 새 이미지에서 가설을 세우고 한계를 포함해 설명한다. | “새 도메인에서 무엇을 먼저 검증할 것인가?” | 실험 계획, 발표 녹음, 질의응답 |

## 프로젝트 사실 경계 점검

- [ ] Top 3 suitability score는 단일 이미지의 **실험 우선순위**이며 분류 정확도가 아님을 설명할 수 있다.
- [ ] benchmark는 117장·6개 `tile/test` 상태 폴더 클래스, stratified 5-fold, seed 42라는 범위를 말할 수 있다.
- [ ] Original + RTrees의 Accuracy 0.804, Macro F1 0.789을 특정 실험의 관찰로 말할 수 있다.
- [ ] 이 수치가 공식 MVTec anomaly-detection metric이 아니며 GT mask·localization을 쓰지 않았음을 말할 수 있다.
- [ ] SIFT BoW는 구현되어도 현재 benchmark profile에 없고 fold-local vocabulary가 필요함을 말할 수 있다.

근거를 다시 확인할 때는 [benchmark evidence](../portfolio/benchmark-evidence.json), [평가 코드](../../src/opencv_preprocessing_advisor/evaluation.py), [한계](../portfolio/limitations.md)를 사용한다.

## 발표 리허설

### 1분 버전

- [ ] 문제: “보기 좋은 전처리와 분류에 유리한 전처리는 다를 수 있다”를 말한다.
- [ ] 설계: 진단 기반 후보와 레이블 기반 평가를 분리한 이유를 말한다.
- [ ] 증거: 117장·6클래스·5-fold·seed 42와 Original + RTrees 0.804/0.789을 범위와 함께 말한다.
- [ ] 한계: 공식 anomaly-detection 성능이 아니고 새 도메인 검증이 필요하다고 말한다.

### 5분 버전

- [ ] 입력 계약과 BGR/LAB 선택을 예시로 설명한다.
- [ ] `ImageDiagnostics`와 YAML pipeline이 이유·경고를 만드는 흐름을 그린다.
- [ ] 원본 baseline, 후보 전처리, combined feature, SVM/kNN/RTrees 비교를 설명한다.
- [ ] fold-local scaling과 Macro F1·confusion matrix가 필요한 이유를 설명한다.
- [ ] Original 우세를 실패가 아니라 검증된 결론으로 설명하고 다음 ablation을 제시한다.
